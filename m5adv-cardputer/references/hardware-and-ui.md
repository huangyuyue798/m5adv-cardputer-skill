# 硬件特性与图形化 UI 规范

## 屏幕与硬件

- Cardputer ADV：240×135 TFT，ESP32-S3FN8，8MB Flash，**无 PSRAM**。
- 主循环栈仅 8KB——**大缓冲必须用 `static` 或全局**，绝不能在函数栈上开大数组，否则栈溢出导致黑屏重启。

## 颜色：必须 16 位 RGB565

- M5GFX 颜色是 16 位 RGB565。写 24 位 `0xRRGGBB` 会被静默截断成错误颜色（曾导致整屏变绿）。
- 正确写法：`static const uint16_t C_GOLD = 0xFCA0;`
- 常用主题色（可直接用）：
  ```cpp
  C_BG=0x0008  C_BOX=0x0014  C_LINE=0x03A9  C_CYAN=0x07FF
  C_GOLD=0xFCA0  C_ORANGE=0xFC60  C_GREEN=0x07E0  C_RED=0xF108
  C_WHITE=0xC618  C_DIM=0x632C  C_BLUE=0x105F  C_PURPLE=0x8013
  ```
- 颜色换算：RGB565 = `((R>>3)<<11)|((G>>2)<<5)|(B>>3)`，可用脚本算好再写死。

## 按键映射

- 方向键实际是 `;` `,` `.` `/`（上/左/下/右），在 `readKey()` 里映射成 `^` `v` `<` `>`。是否兼容 WASD 看项目需要——如果页面有**拼音/字母输入**（如搜索框），就别把 w/a/s/d 映射成方向键，否则这些字母打不出来。`OK` = Enter(10)，`ESC` = Del(27) 和 fn+`` ` ``（keysState.word 里的反引号字符，两处都要判），`Tab` = 9。
- 按键去抖：用**按下沿 + 等松键**。不要用 `M5Cardputer.Keyboard.isChange()` 这类有状态 API——曾导致"按一次后全部按键失灵"。
- **自定义等待循环返回前也必须等松键**（不只是 readKey）：若某流程（如"OK 或摇一摇"等待）检测到 enter 就直接 return，紧接着的下一个 `waitKey()` 会把**同一次按住的按键再读一遍**，造成一次 OK 连跳两页。修法：函数内按键触发 return 前循环 `update()` 等 `isPressed()==false`（≤600ms 超时）+ `delay(50)`；传感器/摇动触发无按键则不等。
- 键盘状态每帧由 `update()` 重置；`Tab` 只在特定页有用途，不要当通用返回键。

## 中文显示

- 每处 `setCursor/print` 前确认 `setFont(&fonts::efontCN_12/14/16)` 已设置。
- 「大」「小」渲染异常见 preflight.md 第 4 条。

## UI 开发第一步：先定主题（Python 模拟页确认）

新项目或大改版时，**先定主题风格，再写固件 UI**。直接在 240×135 真机上反复编译烧录确认配色/布局非常慢，正确顺序是：

1. **出首版主题方案**：先定一套主题（背景色、卡片配色、选中高亮、字体字号、图标风格、header/footer 布局），给出 1~3 个候选方向。
2. **生成 Python 模拟页面**：用 Python 写一个本地 HTML 模拟页（内嵌 CSS，按 240×135 等比例画出主菜单和 1~2 个关键内页），启动本地 HTTP 服务后用浏览器预览。模拟器不追求功能，只精准还原视觉：配色、圆角卡片、图标、字号、选中态、提示条都要和最终固件一致。
   - 配色必须和固件共用同一套 RGB565 值（换算成 CSS `#RRGGBB`），避免"模拟好看、烧出来变色"。
   - 字体用 efontCN 对应的中文观感（浏览器中文字体 + 相近字号），让用户在模拟页就能判断中文显示效果。
3. **让用户确认**：把预览给用户看，问风格是否满意。不满意就改配色/布局/图标，重新生成模拟页，循环直到用户点头。
4. **定了就锁定主题**：用户确认后，把这套主题色/字号/布局写成固件的常量（如 `C_BG/C_BOX/C_LINE/C_GOLD ...` 与 UI 组件函数），**后续所有页面照此实现，不再随意改风格**。版本号升级也别动主题，避免每次烧录后界面风格漂移。

要点：主题确认这一步发生在写任何业务页面之前，是整个 UI 的地基。先把主题"定死"，后面各页面才有一致的设计语言；否则边做边改配色，最后整机会东拼西凑。

## 图形化主菜单（不要做普通文字列表）

- 用 **4×2 网格卡片**：每格一个圆角描边框 + 自绘图标（`drawRect/drawCircle/drawLine/fillTriangle` 等几何图形）+ 中文标题。
- 深色仪表盘风格：近黑深蓝底 + 青色描边 + 金橙高亮当前选中项。
- 底部固定一行圆角提示条（`uiFooter`），写清当前页可用按键，如 `^v 选择  <> 调节  OK 进入  ESC 返回`。
- 方向提示用直观符号 `^v<> 方向`，不要写容易混淆的键位符号。

## 避免页面错位

- 屏幕只有 135px 高，可用区约 y=22~112（header 到下，footer 到上）。
- 每行文字高度：12 号字体约 13px、16 号约 20px；排布时按行高累加，别 exceeding footer。
- 结果页信息行与仪表盘/宫格最下排容易重叠——压缩行距或把信息移到独立面板。
- 调整后务必实机拍照核对（模拟/想象不可靠）。

## UI 无闪烁：持久框架 + 局部重绘（重点）

M5GFX 默认画一步刷一步。整屏 `fillScreen()` + 逐图元 `print` 是"闪屏"的根源。按以下分层做，可做到页面切换与内容变化时背景和上下块完全静止。

### 1) 事务：一个绘制批次一次上屏

- `startWrite()` 开事务、所有绘制进缓冲，`endWrite()` 一次提交。**一个批次只提交一次**。
- 反面教材：`clearAndTitle()` 内部已 `endWrite()`，随后又逐行 `print` 正文 → 每行立即刷屏 → 文本"逐行冒出"式闪烁。正文必须放进同一事务。
- 切页闪"空框架再冒字"：整页绘制被拆成多次事务提交（标题一次、正文一次、footer 一次）。改成单个事务画完 header+正文+footer。

### 2) 持久框架：背景与上下块只画一次

- 所有页面若 header/footer 几何一致（顶块 `uiBox(3,3,W-6,16)`、底块 `uiBox(3,H-18,W-6,15)`），把它们 + 屏幕底色做成**持久层**，用 `g_frameValid` 标记，只在首次/失效时画。
- `uiEnsureFrame()`（事务内）：失效时才 `fillScreen(C_BG)` + 画两个圆角块。
- `uiStart()`：不再 `fillScreen`，改为 `uiEnsureFrame()` + 只擦内容区 `fillRect(0,20,W,H-38,C_BG)`。
- `uiHeader()`/`uiFooter()`：不再重画圆角框，只擦**框内文字行** `fillRect(框内,C_BOX/C_BG)` 再写文字，圆角框常驻不动。注意擦除高度要覆盖整行字样但不碰上下边框。
- **框架失效点**：二维码页、配网页这类整屏覆盖（白底）会毁掉框架，从它们返回后必须调 `uiInvalidateFrame()`，下次 `uiStart` 自动重建。
- 内容区里的各页卡片框属于"内容"，随内容重画即可，不算框架。

### 3) 静态等待页只画一次

- 内容不变、只等 OK/ESC 的页（起手提示、落定结果、仪表盘等）：把绘制移到 `while(true)` 外只画一次，循环内只 `waitKey()`。原来每轮整页重绘是纯浪费。
- 若从下层浏览页（文言/详情）ESC 回退可能回到本页，回退后补一次重绘。

### 4) 内容会变的页：只刷变化区

- 拆成"无事务内部绘制函数"（`paintXxxBody()` / `paintXxxFooter()`，调用者保证在事务内）+ 整页版（一次事务）+ 局部版（单独事务只刷变化区）。
- 滚动/翻层只调局部版；切换层/字段才调整页版；无关按键 `continue` 不重绘。
- 设置/日期时间/这类卡片页：卡片框是骨架，调节时只擦卡片内部重画。
- 列表页：把列表区单独做局部绘制函数，光标移动只刷列表区。

### 5) 激进局部更新示例（日历换日）

- 骨架（卡片外框 + 星期行）持久；同月换日只更新：header 日期文字 + 旧/新两个格子（先擦整格去旧高亮再画新高亮）+ 右侧文字区。跨月/切视图/从详情返回才整块重画。
- 状态追踪：`g_view/g_year/g_month/g_day/g_needFull`，判断"同视图同月仅换日"走局部，否则整块。

### 6) 列表可视行数要按像素算，不按数组长度

- 症状：向下选择时高亮画到 footer 外、画面"不往上走"。
- 根因：一屏显示行数固定写死（如 7 行），但实际列表区像素只容得下 4 行。
- 修法：按列表区高度算 `SHOW_MAX`，加滚动窗口偏移 `g_scroll`，让选中项始终落在可视区内。

## 配网与二维码（曾"加载不出二维码"）

- 配网用 Captive Portal：设备开 AP，手机连上后访问 `192.168.4.1`；Web 表单配置 WiFi/AI/亮度/音量等，NVS 持久化。
- 二维码是**自包含实现**（`qrcode.cpp/.h`），无外部依赖。
- **二维码不显示的头号原因：栈溢出**。QR 编码的大对象（`dataBuf/allCode/QRBuilder/trial/tb`、portal 里的 `QRCode qr`）必须声明为 `static`/全局，放 8KB 主循环栈上必然溢出、二维码空白。
- 开机不要进强制配网循环：开机直接进主菜单，未配网时 AI 功能不可用（用 `aiReady()` 门禁），配网写在独立菜单项里。

## 设置页

- 必备三项：屏幕亮度、提示音量、日期时间；再加一行只读版本号。
- 亮度/音量：`^v` 选、`ok` 调节，实时生效并写 NVS；日期时间用 `settimeofday()` 应用，可脱离 NTP 手动校时。
- 版本号用常量 `FW_VERSION`，每次迭代 +1，在设置页显示，方便实机确认烧录的是哪一版。若版本多到设置页塞不下，把版本号挪到 header 右侧。
- 日期互逆：手写 JDN 反算易错（曾出现 70 年偏移），用严格互逆的 `fortuneDaysFromBase()` / `baseToSolar()` 成对实现。
- **空闲自动降亮度省电**（电池供电设备建议做）：配置三件套 `idleDimEnable / idleDimTimeout(分钟) / idleDimLevel(亮度值)`，设置页给一个子页面调开关/时长/目标亮度。全局 `noteActivity()`（任意按键 → 刷新活动时间 + 若已降亮度则恢复常亮）、`idleTick()`（空闲超时 → `setBrightness(idleDimLevel)`），挂在所有 `waitKey()` 的等待循环里。目标亮度要低于常用亮度且 clamp 不超过常亮值。

## 省电（电池供电设备通用方案）

电池供电的 Cardputer 项目建议做下面四层省电，按收益/风险从高到低。全部经验来自真机实测，接入任何项目都适用。

### 1) 对时后关 WiFi，用时按需重连（收益最大、风险最低）

- 症状：开机连 WiFi 对时后射频一直挂着，待机电流居高不下（modem sleep 下仍约 80–108mA，全速 145mA），而离线功能根本不用网。
- 修法：`setup()` 里 NTP 校准完成后立刻 `WiFi.disconnect(true); WiFi.mode(WIFI_OFF);` 关闭射频。
- 关键：所有联网入口必须能"按需重连"——在云端 AI / 网络请求前检查 `WiFi.status() != WL_CONNECTED` 就调 `wifiConnect(timeout)`，失败才报错。底层 HTTP 函数里也保留一次断线重连兜底，形成闭环。**关 WiFi 前务必确认每一条联网路径都有重连，否则功能会静默失效。**
- arduino-esp32 2.x 默认已是 `WIFI_PS_MIN_MODEM`，显式 `WiFi.setSleep(true)` 无额外收益，无需折腾。

### 2) 空闲熄屏：默认值与可见性

- 三件套 `idleDimEnable / idleDimTimeout(分钟) / idleDimLevel(亮度值)` + 全局 `noteActivity()`（按键恢复）/`idleTick()`（超时降亮度），详见"设置页"节。
- **默认参数经验值：空闲 1 分钟、目标亮度 3%（约 8/255）**。1% 太暗，屏幕实际不显示（看着像黑屏/坏屏），别设到 1%。
- 设置页调亮度时步进要细（如 ±2），下限别卡太高（否则调不到 3%）；改完默认值要用 cfgVer 迁移强制覆盖旧配置的 `idleDimLevel`，否则老设备不生效。

### 3) CPU 降频（试验性，做成可开关）

- 做法：空闲熄屏时 `setCpuFrequencyMhz(80)`，任意按键在 `noteActivity()` 里**先恢复 240MHz 再处理业务**（保证网络请求/TLS 算力充足）。
- 必须做成配置项（如 `cpuDownclock`，默认开但可关），方便用户 A/B 实测后决定保留——降频可能影响刷新/蜂鸣精度，不是所有场景都划算。
- 注意与第 1 条配合：降频发生在 WiFi 已关的待机期，重连前已恢复主频，二者不冲突。

### 4) 电池图标与充电误区

- 电池图标自绘即可（外框 `drawRect` + 正极头 `fillRect` + N 格电量 `fillRect`），按百分比阈值分格（如 0/33/66/80 亮 0/1/2/3 格）。**颜色统一用主题色**（如青色），不要绿灯/金/红分色——多色在主题界面里突兀，用户常要求统一。
- **充电由硬件充电 IC 自动完成，软件写不了也不需要写"电源驱动"**；M5Unified 的 `Power_Class` 已驱动（`getBatteryLevel()/getBatteryVoltage()`）。
- 充不进电的首要排查点是**机身侧面电源开关必须拨到 ON**（官方明确：charging 时 switch to ON；OFF 时电池断开、只用外部供电）。其次是快充头/USB-C to C 线不兼容，换 5V 普通充电器 + 数据线。
- Cardputer/Adv **硬件读不到"是否正在充电"和充电电流**，别做"充电中"状态显示；新电池头几次循环可能卡在 75–80% 不动，属正常；从空电充满约 7 小时。

## 时间持久化（无 RTC 电池）

- Cardputer 类设备没有 RTC 纽扣电池，断电后系统时钟丢失。只在 setup 里 `configTime()` 异步校准是不行的——没网/未校准完成时时间是 1970，页面会退回编译日期。
- 通用方案：NVS 存 UTC epoch（秒）。`timeSaveNow()`：仅当 `time()>阈值` 时 `putUInt("utcEpoch", now)`；`timeRestore()`：开机若系统时钟无效则读 epoch `settimeofday()`。
- 保存时机：NTP 校准成功后（setup 里 `configTime()` 后轮询等 `time()` 有效，最多几秒）、用户手动设置时间后、以及等待循环里节流周期保存（如每 60s 一次，把断电误差压到分钟级）。
- 实话说明：无硬件 RTC 无法计关机时长，恢复的是"上次保存时刻"，误差 ≤ 保存间隔；联网后 NTP 会自动校准。

## 多层级结果页交互（通用模式）

- 若结果有多层内容（如图形概览 → 简要说明 → 详细解释 → AI 分析），用 `OK` 逐层深入。
- 详情首屏"总结前置"：先给一句话结论，往下翻才是展开细节。
- `ESC` 逐级回退：深层 → 浅层 → 图形概览页（不要直接退回主菜单）。用一个层级状态机（如 `g_layer`）管理当前层与回退路径。
- 每个流程里浏览层返回后要继续循环重绘上级页面，不要直接 `return` 跳回主菜单。
- 各占卜流程里 `browseTextResult()` 后要继续循环重绘仪表盘，不要 `return` 回主菜单。

## 栈与内存通用规则

- 大数组（QR、音频缓冲、JSON 文档、响应缓冲）一律 `static` 或 `malloc` 堆分配、用完即释放。
- `DynamicJsonDocument` 不要放栈上；`WiFiClientSecure` 用栈对象并确保 delete/析构，避免每次请求泄漏。
- 音频录制缓冲走堆分配 + 用完 free，控制时长（如 4 秒 @16kHz）。
